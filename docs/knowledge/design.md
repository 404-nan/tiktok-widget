# デザイン判断

## 判断の軸

- [docs/DESIGN.md](../../docs/DESIGN.md) が詳細な基準。[docs/IDEAS.md](../../docs/IDEAS.md) は実装済みと将来案を分けたアイデア集。
- 画面に出る文は日本語。やさしい言葉を使い、専門用語だけにしない。
- 面は不透明な平面。意味のないグラデーション、ぼかし、半透明の薄い文字を使わない。
- 基本色は墨・白・朱・金。期待度は青 → 緑 → 赤 → 金 → 虹で覚えられるようにする。
- 文字を増やすより、色・光・音・揺れ・間で伝える。主役はギフトを送った人。

## 操作画面

- ダッシュボード、管理画面、モニター、統計は同じ部品と見た目にそろえる。
- まず「かんたん」を見せ、細かい設定やYAMLは「くわしく」に畳む。サイドバーで切り替え、不要な画面遷移を増やさない。
- スマホでも押せる大きさ、本文16px、十分なコントラストを守る。画面変更後はPC・スマホ、明暗を撮影する。

## 演出と実装

- 溜めてから放つ。カットイン、RUSH、WIN数、スロットは短く、段階と音の落差を使う。
- 状態と抽選はサーバー側。画面側はWebSocketのイベントを受けて演出する。
- 公開ウィジェットはChromium 103相当の制約を意識し、CDNを使わず ES2022 までの書き方で書く(Chromium 104 より新しい関数は使わない)。
- スロットの細部は [docs/slot-design/spec.md](../../docs/slot-design/spec.md)。ギフト名は対応表から日本語で表示する。
