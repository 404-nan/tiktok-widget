# 開発の流れ

## 完成まで

1. まず完成条件カードを短く作る。画面なら対象サイズ、状態、表示文、操作を含める。
2. 別のAIに受け入れテストを書いてもらい、失敗条件を先に決める。
3. 実装する。設定項目を増やすなら `src/schema.js` と画面の説明も同時に更新する。
4. `npm test` を実行し、全テストを緑にする。
5. 見た目を変えたら開発サーバーで撮影する。PC・スマホ、明るい・暗い表示を確認する。
6. 別のAIにコードと撮影結果をレビューしてもらう。
7. 本番へ出す前にオーナーが見て確認する。

## ブランチとworktree

- 作業は本番ブランチから分けた `dev/*` 等のブランチで行う。複数のAIは別worktreeを使う。
- 変更前に `git status` とブランチを確認する。既存の未コミット変更を消さない。
- `main` や本番ブランチへ push しない。コミットは依頼されるまで不要。

## テスト

- テストランナーは `node --test`、実行は `npm test`。
- 既存の `test/*.test.js` のNode標準テスト、fixture、一時ディレクトリの流儀に合わせる。
- 本番データをテストに使わない。設定・保存処理は一時ファイルを渡す。
- UI変更は可能ならPlaywrightで開発サーバーを撮影し、文字・コントラスト・スマホ幅も見る。

## 道具（tw-flow）

- `tw-flow status`: 本番・開発サーバーが今どのコミットか、本番にまだ入っていない `dev/*` ブランチの一覧。
- `tw-flow preview <branch>`: 開発サーバー(3940, dev.lul.works)をそのブランチにする。テストが通らなければ切り替えない。
- `tw-flow clean`: 本番に入り終わったブランチの worktree を片付ける。ブランチは残るので戻せる。
