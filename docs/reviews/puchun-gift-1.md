# レビュー: puchun-gift 

**【直す】見本ボタンがない(AC-2)**
- `puchunTestPlay`(`src/puchun.js`)は、テストからしか呼ばれていません。`src/` と `public/dashboard/` を grep しましたが、本番の呼び出しはありませんでした。
- ダッシュボードに「見本を出す」ボタンも、それを受けるサーバー側の入口もありません。保存した字を、その場で1回流すことはできません。
**【直す】連打が「順に」ではなく同時に流れる(AC-3)**
- `src/runtime.js:208` が個数ぶんの `puchun` メッセージを一度に送ります。
- `public/widgets/puchun/puchun.html` は、受け取るたびに iframe を作り、固定の時間(2200〜8000ms)で消します。待ち行列も、前の演出が終わるのを待つ処理もありません。
- ×5 なら5本が重なって同時に出ます。×200 なら iframe が200個でき、それぞれが WebGL と `warm()` を動かすので、配信ソフトが重くなります。
- テストが見ているのは `puchunPlays` が個数ぶんの配列を返すことだけで、画面で順に流れるかは確かめていません。
- `puchun.html` の `doesNotMatch` の正規表現は、`shift()` を使っていなければ必ず通ります。上限がないことの証明になっていません。
**【直す】証拠の画面がない**
- `artifacts/shots/` がありません。カードが求める、dev(3940)でスマホ幅とパソコン幅の画面を撮ったものがありません。
- 一番上の README は「できた(開発サーバーで確認)」と書いていますが、実際には確認した形跡がありません。
**【直す】管理者が機能を止めても流れる**
- `src/runtime.js` の `puchuns` は `FEATURE_ORDER` に入っています。ところが `hub.on('event')` の中の `puchunPlays` は `entitled('puchuns')` を見ません。
- 他の機能は `entitled(...)` で止める作りです(`runtime.js:253` 以降)。管理者が `puchuns` を使えない設定にしても、配信者の設定どおり流れます。
**【直す】字の入力が「その演出のキー全部」になっていない(AC-2)**
- `texts` は生の JSON テキストエリアだけです(`editor.js` の `type: 'object'`)。演出を選んでも、その演出のキー(`main`・`sub`・`say`・`num` など)の入力欄は出ません。
- 配信者が JSON を自分で書く必要があります。JSON が壊れていると、メッセージが出るだけで保存されません。
- schema と config は `texts` のキー名や型を確かめていません。数値やネストした値も通り、`puchun.html` 側で `query.set` に渡されます。
**【直す】一番上の README の行が食い違っている**
- 同じ表に、新しい「パチンコ演出 / できた」の行と、古い「パチンコ演出(見本) / ギフトとのつなぎはまだ / 作りかけ」の行が両方残っています。
- 古い行は今の状態と矛盾するので、直す必要があります。
- AC-6 のテストは「パチンコ」を含む最初の行しか見ないため、この矛盾に気づけません。
**【軽い】`texts` のキーが iframe の指定を上書きできる**
- `puchun.html` は `preset`・`ratio`・`play` を先に `query` に入れ、その後 `texts` のキーを `query.set` します。
- `texts` に `play`・`ratio`・`preset`・`t`・`hold` などのキーがあると上書きされます。たとえば `hold: '1'` を入れると演出が動きません。
- `texts` のキーを、その演出の `fields` のキーだけに絞る必要があります。
**【軽い】`texts` の字数が入力の段階で制限されていない**
- 20字の切り詰めは描画側にだけあります。保存と指示には長さの制限がなく、URL が長くなりえます。
**【軽い】設定の特例**
- `puchuns` だけ `defaultsFor` と `checkFields` に特例を入れています(`config.js:561`、`schema.js:985`)。
- 他の map 型と形が違うので、`defaultsFor('puchuns')` を使う既存の共通処理が、この形を前提にしていないと崩れるおそれがあります。
**既存への影響とテストの結果**
- `npm test` は 782 件中 780 件が通り、2 件はスキップ、失敗は 0 でした。
- 前からあるテストを弱めた形跡は見つかりませんでした。
**カードに無い追加や変更**
- フォント(Reggae One)の woff2 ファイルとライセンスを追加しています。カードは `dev/puchun` を cherry-pick する前提なので、ここは許容範囲です。
- `editor.js` に汎用の `object` 型の入力を足しています。これは `texts` 用の変更です。
