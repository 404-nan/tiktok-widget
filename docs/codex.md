# Codex の使い方

Codex は実装係・受け入れテスト係・レビュー係のどれにもなる。書いたAIと、そのテスト・レビューをするAIは必ず分ける。

| 列 | 実装する | 受け入れテストとレビューをする |
| --- | --- | --- |
| A列 | Codex | Claude のサブエージェント |
| B列 | Claude のサブエージェント | Codex |

動かし方:
- レビュー: `codex exec --sandbox read-only "<依頼文>" < /dev/null`(標準入力を閉じないと、裏で動かしたとき入力待ちで止まる)
- 受け入れテスト・実装: 作業場所(worktree)の中だけ書ける設定で `codex exec --sandbox workspace-write -C <worktree> "<依頼文>" < /dev/null`
- Claude が受け入れテストを書くとき(A列)は、実装とは別のプロセスで `TW_GUARD_ROLE=acceptance claude -p --model sonnet "<依頼文>"` として起動する。この環境変数があるときだけフックが test/acceptance/ への書き込みを通す
- Codex には Claude Code のフックが効かない。守るファイルは CI(`.github/workflows/check.yml`)とブランチ保護・CODEOWNERS で止める

## 受け入れテストを書く依頼(実装より先)

```
次の完成条件カードを読んで、各ACを確かめるテストを test/acceptance/ に書いてください。
実装はまだ無いので、今は失敗するはずです。失敗することを確認してください。
実装の都合に合わせてテストを甘くしないでください。カードに無いことはテストしないでください。
カード: <パス>
```

## 実装の依頼

```
次の完成条件カードを満たす実装を、この作業場所の中だけで行ってください。
受け入れテスト test/acceptance/<名前> がすでにあります。テストは変えずに、テストが通るように実装してください。
カードに無い機能は足さないでください。終わったら npm run check の結果と、変えたファイルの一覧を返してください。
カード: <パス>
```

## 独立レビューの依頼(実装の後)

```
あなたはこの変更を書いていません。次の4つを見て、問題だけを報告してください。
1 完成条件カード <パス>
2 差分 git diff <土台>...HEAD
3 テストの結果 <npm run check の出力>
4 画面 <artifacts/shots のパス>
報告すること: カードを満たしていない箇所 / 既存機能を壊していそうな箇所 / カードに無い追加や変更 / テストが弱い箇所 / 本番で起きそうな問題。
好みの指摘や新しい機能の提案はしないでください。問題が無ければ「問題なし」とだけ書いてください。
```
