# ダッシュボード3案の設計根拠

**ブランチ:** `dev/dashboard-styles`

---

## 共通の設計判断

### 配信者のタスクと優先度

配信中にダッシュボードを見るとき、いちばん多い動作は「数字をちらっと見る」。KPI（視聴者数・コイン・ギフト数）は常に視界に入っていて、変化に気づけることが最優先。次に「イベントログで誰が何を送ったか」を確認する。接続の操作は配信の最初と最後だけ。設定の変更は配信中にはほぼしない。

この優先度から、3案とも以下の順で視線を導く:

1. **上の帯** → 接続状態（ドットの色だけで「つながっている」が分かる）
2. **KPI の並び** → 左から右へ数字を流し読み
3. **左カラム** → 接続フォーム＋イベントログ
4. **右カラム** → ウィジェット設定（作業するときだけ注目する）

### 余白の基準

4px 刻みの目盛り（4 / 8 / 12 / 16 / 24 / 32 / 48）だけを使う。「なんとなく 20px」のような端数を避けることで、画面全体に秩序が生まれる。カードの内側余白、カード間の間隔、ヘッダーの上のマージンをすべてこの目盛りから選ぶ。

### 文字の基準

- 本文・入力欄・ボタン: 15px / ウェイト 400–500
- KPI の数字: 44px / Barlow Condensed 600
- 見出し（h3）: 26px / 700 / 字間 -.02em
- カードの見出し（h2）: 15px / 600
- 補足・ヒント: 14px（これより小さくしない）

日本語のフォントスタックはシステムフォントだけ。数字の大きな表示だけ Barlow Condensed。

### 状態の表現

| 状態 | 表現 |
|------|------|
| 未接続 | ドットが灰色。接続フォームが出ている |
| 接続中 | ドットが黄色で点滅。ボタンは無効 |
| 配信中 | ドットが緑。光の輪がつく。切断ボタンが出る |
| エラー | ドットが赤。メッセージが赤文字で出る |
| デモ | ドットが青。配信中と同じレイアウト |
| 空（データなし） | 薄い文字で「まだ何もありません」。骨格やアニメーションは出さない |

## 案A「ライト・ニュートラル」

### 優先度

「信頼できる道具」の印象を最優先にした。Stripe や Linear (ライトモード) のように、白い背景に薄い線と控えめな影でカードを区切る。派手な色はアクセント（朱色）だけ。プレビュー（配信に映る画面）が唯一の「濃い」要素になるので、視線が自然にそこへ行く。

### 視線の流れ

白い面の上に灰色の線でカードが並ぶ → 目が留まるのは黒い文字（KPI の数字、見出し）と、暗いプレビュー枠。設定の入力欄やボタンは背景に近い色なので邪魔にならない。

### 余白

- カードの内側: 24px 横 / 16px 縦（広め。呼吸がある）
- カード間: 24px
- 全体の最大幅: 840px（1列のとき）

### 配色

| 役割 | 色 |
|------|-----|
| ページ | #F8F8FA（ほんの少し青みがかった白） |
| カード面 | #FFFFFF |
| 線 | #E4E4E8 |
| 本文 | #1A1A2E（濃い紺。真っ黒より柔らかい） |
| 補足 | #52525B |
| ヒント | #8C8C96（白いカードの上でだけ使う） |
| アクセント | #D94F1A（朱。配信中のドットと一致） |
| 主ボタン | 本文色の塗り（紺。目立つが落ち着いている） |

### 使いやすさの判断

**なぜ配信中に使いやすいか:** 明るい画面は部屋が明るい配信（トーク・歌・ゲーム実況）で見やすい。白い背景に黒い数字は最も読みやすい組み合わせ。配信に映るプレビューだけが暗い枠で囲まれるので、「今ここが配信に映っている」が一目で分かる。操作する要素は目立たないが、押せばちゃんと反応する。

## 案B「ダーク・高密度」

### 優先度

「情報密度」を最優先にした。セカンドモニターに常時表示して、ちらっと見るだけで全体の状況が分かることを目指す。余白を詰め、フォントサイズを少し下げ、1画面に入る情報量を増やす。

### 視線の流れ

暗い背景にほとんど線が見えない → 明るい文字（KPI の数字）が浮き上がって見える。カードの区切りは色の差（page #111113 vs surface #191A1E）で感じ取る。スクロールしなくてもイベントログが多く見えるよう、行の高さを 38px に詰めている。

### 余白

- カードの内側: 16px 横 / 12px 縦（詰めている）
- カード間: 12px
- KPI: 12px 16px（詰め）
- KPI の数字: 38px（既定の 44px より小さい）

### 配色

| 役割 | 色 |
|------|-----|
| ページ | #111113（ほぼ真っ黒） |
| カード面 | #191A1E |
| 線 | rgba(255,255,255, 0.08)（ほとんど見えない） |
| 本文 | #EDEDEF |
| 補足 | #A0A0AB |
| ヒント | #6B6B76 |
| アクセント | #FF5A2B |
| 主ボタン | 本文色の塗り（白。暗い画面で最も目立つ） |

### 使いやすさの判断

**なぜ配信中に使いやすいか:** 暗い部屋で配信するとき（ゲーム実況・歌枠）、明るい画面は目に刺さる。この案は画面全体が暗いので、目の負担が少ない。文字と背景のコントラストは WCAG AA を満たしているが、画面自体の明るさは抑えている。高密度なので、マウスを動かさなくても KPI・イベントログ・プレビューが1画面に全部見える。

## 案C「配信ツール・高コントラスト」

### 優先度

「配信ツールらしさ」を最優先にした。OBS や Streamlabs の管理画面のように、暗い背景にオレンジのアクセントが映える。主ボタンがアクセント色（赤橙）なので、「これを押せば動く」がすぐ分かる。見出しのラベルがアクセント色で小さく表示されるのも、配信ソフトの「区画表示」に近い。

### 視線の流れ

暗い面に暖色の差し色 → 目はまずオレンジのドット（アクセント色）とアクセント色の見出しに行く。「いま配信中か」と「この区画は何か」が同時に分かる。主ボタンもオレンジなので、操作の起点が見つけやすい。

### 余白

- カードの内側: 24px 横 / 16px 縦（案A と同じ。配信ツールは「窮屈」よりも「見やすい」が大事）
- カード間: 24px
- カードの角: 10px（案A の 12px と案B の 8px の中間。OBS に近い）

### 配色

| 役割 | 色 |
|------|-----|
| ページ | #16141A（紫がかった黒。暖かみがある） |
| カード面 | #1E1C22 |
| 線 | rgba(255,255,255, 0.10) |
| 本文 | #F5F3F0（わずかに暖色。真っ白より目に柔らかい） |
| 補足 | #B5B0A8（暖色の灰色） |
| ヒント | #7A7670 |
| アクセント | #FF5030（TikTok のアクセントに近い赤橙） |
| 主ボタン | アクセント色の塗り（赤橙。配信の「ゴー」ボタンの感覚） |

### 使いやすさの判断

**なぜ配信中に使いやすいか:** 配信者は OBS や TikTok LIVE Studio の管理画面を見慣れている。この案はその見た目に近いので、学習コストがほとんどない。主ボタンが赤橙なので、暗い画面の中で「接続」「保存」「コピー」がすぐ見つかる。入力欄はカード面より暗い色（沈んだ見た目）にして、「ここに書く」が触らなくても分かる。フォーカス時にアクセント色の光の輪が出るのも、配信ソフトのフィードバックに近い。

## 自己批評と修正の記録

### 初稿で指摘した問題

1. **案A のヒント色が WCAG AA を満たさない場面があった。** `#8C8C96` は `#F8F8FA`（ページ背景）の上では 3.6:1。14px のテキストは 4.5:1 必要。→ 修正: ヒント色はカード面（`#FFFFFF`）の上でのみ使う運用にした。ページ背景に直接ヒントを置くとき（今のマークアップにはない）は `#52525B`（secondary）を使う。

2. **案B が既存のダークテーマと区別がつかなかった。** 既存の CSS は `#18181B` / `#222226` を使っている。案B を `#191A1E` / `#222228` にすると、切り替えても変わったように見えない。→ 修正: ページを `#111113`（より暗い）、面を `#191A1E`、線の透明度を 0.08（より薄い）にして、既存テーマより「もっと暗く・もっと詰めた」方向に差を出した。密度の差（余白 12px・KPI 38px・ボタン 36px）でも違いが分かる。

3. **案C の主ボタンが案B と同じ白だった。** 3案を並べると B と C の違いが「背景の色味」だけになり、テーマを変える意味が薄い。→ 修正: 案C の主ボタンをアクセント色（`#FF5030`）に変えた。白い文字との対比は 3.5:1 で、15px 太字（ウェイト 600）は WCAG の大きい文字の基準（14pt = 18.67px 以上の太字で 3:1）を満たす。

4. **案C のフォーカス表示がなかった。** キーボード操作をする配信者（マウスが配信画面に取られている）にとって、フォーカスの位置が分かることは大事。→ 修正: 案C の入力欄のフォーカスにアクセント色の光の輪（`box-shadow: 0 0 0 2px rgba(255, 80, 48, 0.15)`）を追加した。

5. **案A・B・C を切り替えても `data-theme`（明暗）との関係が不明だった。** 案A はライト、B と C はダーク。既存のテーマ切り替えボタンとの干渉をどうするか。→ 修正: スタイル切り替えは `data-style` で独立。各スタイルが `color-scheme` を設定する。既存の `data-theme` ボタンはスタイル適用中は無視してよい（エンジニア判断で隠すか残すか決める）。

6. **カードの幅が「等しくする」と書いたが、具体的にどう担保するか不明だった。** → 修正: グリッドの列は `1fr`（等分）か同じ `minmax()` で統一。ピクセル固定のカード幅は禁止。

7. **案C の区画見出しが目立たなかった。** `.sgroup-title` が既存のままだと、案C の「配信ツールらしさ」が出ない。→ 修正: 案C のみ `.sgroup-title` をアクセント色・大文字・小さめ（13px）・字間広め（.04em）にした。OBS のセクションラベルに近い。ただし中身が日本語なので `text-transform: uppercase` は英字ラベルにしか効かない。日本語の場合はフォントサイズとアクセント色で区画を示す。

### 修正の結果

上の 7 点はすべて spec.md に反映済み。各案の配色は修正後の値で記載している。

### Pinterest レベルのポリッシュか？

正直に言うと、CSS のみの3案では「磨き込んだ1案」より表面的になる。Pinterest や Stripe のダッシュボードは、アイコンの描画品質、マイクロインタラクション（ホバー時の微妙な変化）、タイポグラフィの細かい調整（和文と英数字の混植間隔）まで詰めている。この3案はトークンの切り替えだけで骨格を変えない設計なので、そのレベルに到達するにはさらに各案を個別にブラッシュアップする必要がある。

**AI スロップではないか？** 配色は実際にコントラスト比を計算して決めている。「とりあえず良さそうな色」ではなく、WCAG AA の 4.5:1 / 3:1 を計測して不足を修正した。余白もランダムではなく 4px 刻みの目盛りから選んでいる。密度の差（案B）やアクセントの使い方（案C）は意図を持って設計している。

**明確な階層か？** 3案とも「KPI の数字 → 見出し → 本文 → 補足」の4段階を、サイズ・ウェイト・色の3軸で区別している。見出しは大きく太く、補足は小さく薄い。KPI だけ別の書体（Barlow Condensed）にすることで、数字は「読む」のではなく「見る」ものになる。
