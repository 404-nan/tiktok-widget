# ダッシュボード3案: 工程・自己批評・改善の記録

**ブランチ:** `dev/dashboard-styles`
**実装:** `public/dashboard/themes.css`（見た目）、`public/dashboard/dash-style.js`（切り替え・ES5）
**スクショ:** `~/dash-shots/`（`dashboard-{a,b,c}-{desktop,mobile}.png`、設定画面は `detail-*`、変更前は `before-*`、3回目の直しのあとは `fix-*` と `fix-detail-*`）

---

## 1. 情報の優先度

いまの「かんたん」画面（PC はサイドバーと右の中身、スマホは上のバーと横に流れるメニュー）で、配信者が目で追う順番を決めた。

1. **つながっているか**: ブランド名の下にある色の点と「未接続 / 配信中」
2. **いまの作業**: 右側の見出し（26px）と、その下のカード（URL の一覧・設定）
3. **押すボタン**: 接続、URL のコピー
4. **場所を変える**: サイドバーのメニュー
5. **めったに触らないもの**: モニター・統計へのリンク、画面の見た目（3案の切り替え）

集計（KPI）とイベントログは「くわしく」用の部品で、今の画面には出ていない。それでも3案の値（38px / 44px、線の色）は当ててある。

## 2. 視線の流れ

- **PC**: 左上のブランド名と接続状態 → 右の見出し → 1枚目のカード → 行ごとのボタン。サイドバーの一番下に「画面の見た目」を置き、作業の邪魔をしないようにした。
- **スマホ**: 上のバー（ブランド・ページ切り替え）→ 接続 → 横に流れるメニュー → 見出し → カード。画面の見た目の切り替えは、めったに触らないのでページの一番下に置いた。

## 3. 余白の決まり

- 4px の目盛り（`--s-1`〜`--s-7` = 4/8/12/16/24/32/48）だけを使う。元の CSS に残っていた 6px・10px・14px・18px などは、案を当てているときはすべて目盛りの値で上書きした。
- カードの内側は `--card-pad-y` / `--card-pad-x`、カード同士は `--card-gap`。案ごとの値は次のとおり。

| | 内側（縦/横） | カード間 | 画面の上 | ボタンの高さ | URL の行 |
|---|---|---|---|---|---|
| A | 16 / 24 | 24 | 32 | 40 | 72 |
| B | 12 / 16 | 12 | 24 | 36 | 56 |
| C | 16 / 24 | 24 | 32 | 40 | 64 |

- カードの中にある行（設定の1項目）も、左右は `--card-pad-x` にそろえた。上下は行の高さとして `--s-3`（B は `--s-2`）にしている。
- 一番上のカードの上にはいつも `--page-top` の余白があるので、画面の上の端に接するカードはない。
- 同じ行に並ぶカードは同じ幅にした。設定画面の左（設定）と右（プレビュー）は、もともと 400px と残りの幅で大きさが違ったので、案を当てているときは `1fr 1fr` にした。

## 4. 文字

| 役割 | 大きさ・太さ |
|---|---|
| 見出し（h3） | 26px / 700 / 字間 -.02em（B だけ 22px） |
| カードの見出し | 15px / 600 |
| 本文・入力欄・ボタン | 15px（ボタンは 14px / 500、主ボタンは C だけ 600） |
| 補足・時刻・呼び名 | 14px（これより小さくしない） |
| 集計の数字 | Barlow Condensed 600（A・C 44px、B 38px） |

仕様では B のサイドバーと C の区画見出しが 13px だったが、「補足でも 14px 未満にしない」という決まり（docs/DESIGN.md と rationale.md）を優先して 14px にした。B の詰まり具合は、文字を小さくするのではなく、行の高さと余白で出している。

## 5. 実装

- `<html data-style="a|b|c">` に当てる CSS を `themes.css` にまとめた。`style.css` は書き換えていない。
- 元の変数（`--page` `--surface` `--text-primary` `--stroke-secondary` `--accent-fill` など）を案の値につないだので、細かい部品（ルールの行・ギフト選び・グラフの吹き出しなど）にも案の色が付く。
- **切り替え**: PC はサイドバーの一番下、スマホはページの一番下に置いた（はじめは上のバーに置いたが、バーが高くなったので移した。14 を参照）。「画面の見た目」と今の案の名前（例:「配信ツール・高コントラスト」）を出し、その下に同じ大きさのボタン3つ（ライト / ダーク / 配信風）を横に並べている。選んだ案は `localStorage` の `dash-style` に残る。`?style=a` のように開くと、その案にして残す。
- **初めて開いたとき**は、今までの明るさの設定（`tw:theme`）に近い案にする（明るい → A、暗い → B）。
- 案を当てているときは、明るさも案が決めるので、明るさを切り替えるボタンは隠した。モニター・統計の画面の明るさの設定（`tw:theme`）は変えない。既存の保存データや API には触っていない。
- 描く前に案を決めたいので、`dash-style.js` は `<head>` で同期読み込みにした。ES5 で書き、`test/es5-public.test.js` の対象に加えた。
- Chromium 103 で動く書き方にした。`:has()`・コンテナクエリ・`color-mix()`・入れ子は使っていない（`:where()` は 88 から使える）。
- グラデーションとぼかしは消した。元の CSS にあった、ログ・メニューの端を薄くするマスク、サイドバーのぼかし、配信画面の見本の傾き、セレクトの矢印（グラデーションで描いていたもの）が対象。矢印は SVG に置き換えた。

## 6. 自己批評と改善

### 1回目のスクショ（v1）で見つけた問題

1. **URL の一覧のカードで線が2重になっていた。** 設定のまとまり（`.sgroup-body`）に付けた枠が、URL のカードの中にもそのまま出て、内側にもう1本線が見えた。
   → URL のカードの中では、まとまりの枠・背景・影を消した。
2. **行ごとの「コピー」が全部、主ボタンの塗りだった。** 12 行ぶん紺（A）や赤橙（C）の塊が縦に並び、どれも主役に見えて目が止まらなかった。特に C では画面の 3 分の 1 が赤橙になった。
   → 行のボタンは2つとも線だけのボタンにした。コピーは文字を太くしてアイコンだけ差し色に、設定は文字を控えめにした。塗った主ボタンは画面に1つ（接続）だけになり、C の赤橙が「押せば始まる」場所だけを指すようになった。
3. **B で見出しが画面の上に近すぎた。** カード間（12px）を画面の上の余白にも使っていたので、窮屈に見えた。
   → 画面の上の余白を `--page-top` として分けた（A・C 32px、B 24px）。
4. **ウィジェットの枠に影が残っていた。** 「かんたん」では面にしない `.widgets` と、サイドバーの接続の枠に、案の `.panel` の影が付いてしまい、A で薄い四角が見えた。
   → この2つは角と影を消した。
5. **スマホで案の名前が途中で切れた。** 名前とボタンを1行に並べたので、「配信ツール・高コ…」になった。
   → 1行目に「画面の見た目　ライト・ニュートラル」、2行目に同じ幅のボタン3つ、という2段にした。上のバーの下の角が丸く残っていたのも直した。
6. **サイドバーで「配信向け」が窮屈だった。** 3つのボタンは 66px で、4文字だと端に当たった。
   → 「配信風」（3文字）にした。正式な名前は上の行に出しているので、意味は伝わる。
7. **オン / オフのスイッチの「オフ」が見えにくかった。** A では溝が白に近く、つまみと見分けにくかった。
   → オフの溝の色を案ごとに決めた（A #8E8E98、B #5A5B63、C #5E5B66）。

### 2回目のスクショ（v2）で見つけた問題

8. **設定画面の「種類」の選択欄が、画面の横いっぱいに伸びていた。** 1行に1つしか入らないので、その下の「名前を変える」などが離れて見えた。
   → 選択欄は 320px までにして、ほかの操作と1行に並べた。
9. **「出しかた」の型（ひかえめ・ふつう・しっかり）が2列で、「しっかり」だけ次の行に落ちていた。**
   → 3列にして、3つが同じ大きさで1行に並ぶようにした。
10. **スマホで「ためす」のボタンの大きさが違った。** 元の CSS では1つ目だけ行いっぱいだった。
   → 2つとも同じ幅で横に並べた。長い名前（見本のギフトを出してみる）は2行に折り、2つの高さをそろえた。
11. **スマホでプレビューと設定の間が大きく空いていた。** 空のお知らせ欄（`.form-message`）が高さを持ったままで、間隔が2つ分になっていた。
   → 空のときは出さないようにした。

### 色の計算（仕様の値を直したところ）

仕様の「コントラストの確認」には計算違いがあった。実際に計算し直して、足りないものは直した。

| 案 | 組み合わせ | 仕様の値 | 実際 | 直した値 |
|---|---|---|---|---|
| A | ヒント #8C8C96 / 白 | 4.6:1 | 3.3:1 | #6E6E78（5.0:1） |
| A | 成功 #16A34A / 白（文字） | — | 3.3:1 | #15803D（5.0:1） |
| B | ヒント #6B6B76 / #191A1E | 4.5:1 | 3.3:1 | #8A8A95（5.1:1） |
| C | ヒント #7A7670 / #1E1C22 | 4.5:1 | 3.7:1 | #8E8982（4.9:1） |
| C | 白文字 / 主ボタン #FF5030 | 3.5:1 | 3.3:1 | 塗りを #D4401F（4.6:1） |

C の主ボタンについて、仕様では「15px の太字は大きい文字なので 3:1 でよい」としていた。しかし WCAG で大きい文字に入るのは、太字なら 18.66px 以上なので、この理由は成り立たない。そこで、塗りを少し深い赤橙にして、白い文字のままで 4.5:1 を満たすようにした。差し色の点や線は、もとの #FF5030 のまま使っている。

線の色も、B・C で `rgba(255,255,255,.08)` のような透ける値だったのを、面の上で同じに見える透けない色（B #26272C、C #34323A）に置き換えた（「面は透けない色」の決まりに合わせるため）。

### 3回目（v3）: 残っていた3つを直した

12. **サイドメニューが一番下で途中で切れ、続きがあることもわからなかった（3案とも。目立っていたのは B）。** メニューはもともとスクロールできたが、元の CSS の「端を薄くするマスク」を外したので、切れた項目がそのまま見えていた。
   → メニューが入りきらないときだけ、下の端に透けない帯を重ね、帯の上の線と「下にまだあります ⌄」を出すようにした。帯の色はサイドバーと同じ1色で、グラデーションは使っていない。
   - 帯の高さは、途中で切れている項目をまるごと隠せる高さにした（`editor.js` で項目の位置から決める）。そのため、線はいつも項目の境目に来て、半分だけ見える項目はなくなった。
   - 一番下まで流すと帯は消え、最後の「使い方」まで見える。帯を押すと、メニューが1画面ぶん下へ流れる。
   - 帯が出ている間は、その下（モニター・統計の上）の区切り線を消した。1回目の試しで線が2本並んで見えたため。
   - 縦に長い画面（1440×1400 で確かめた）では、メニューが全部入るので帯は出ない。
13. **設定画面の見本カードが、左の1枚目のカードより30px上から始まっていた。** 左は区画見出し（「いつ出す」など）と間隔のぶん下がるが、右の見本は列の一番上から始まっていた。見出しの高さが文字の行の高さ（14px × 1.6）で決まっていて、目盛りの値にならないのが原因だった。
   → 区画見出しの行の高さを `--s-5`（24px）に決め、見本の列を `--s-5 + --s-2`（見出し＋間隔 = 32px）だけ下げた。見本の黒い縁の上の端と、左のカードの上の端がそろった（A・C は 211px、B は 198px で同じ）。ギフト通知のほかに、色とテーマ・RUSH・ルーレットなど、見本のあるタブはどれも先頭が見出しつきのまとまりなので、すべて同じようにそろう。スマホは1列なので変えていない。
14. **スマホの上のバーが高かった（188px）。** ページの切り替えの下に、見た目の切り替えが2段（名前とボタン）入っていた。
   → 見た目の切り替えをページの一番下へ移した。上のバーはブランドとページの切り替えの2段だけになり、104px になった（案を当てる前の上のバーとほぼ同じ高さ）。PC の幅に広げるとサイドバーの下へ戻り、スマホの幅に戻すとまたページの一番下に来ることも確かめた。

### まだ残っていること（正直な評価）

- **帯が出ているとき、帯の中は線と1行の文字だけなので、項目の高さぶん空いて見えることがある。** 切れた項目を隠すために帯を高くしているため。空きは最大で項目1つぶん（36〜40px）。
- **スマホでは、見た目の切り替えがページの一番下にあるので、URL の一覧が長いと見つけにくい。** 優先度は一番低いもの（1. の5番）なので、この置き方にした。
- **スマホの横に流れるメニューも、右の端で項目が切れている。** 横に流れることは見てわかるので、今回は手を入れていない。
- **集計とイベントログ（「くわしく」の部品）は、今の画面に出ていないので、スクショでは確かめていない。** 色と余白の値は当ててある。
