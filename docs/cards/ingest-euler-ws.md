# ingest-euler-ws: Euler Stream の公式 WebSocket を、今の鍵・今の契約のまま使えるか

仕事の種類: 調査(「使える」と確かめられたときだけ実装。新しい契約・お金がかかるものは使わない)
見た目が変わるか: いいえ
前提: `ingest.md` ができていること(二重対策に乗せるため)

## 調べて分かったこと(公式の説明書、2026-10-18)
- 接続先: `wss://ws.eulerstream.com?uniqueId=<配信者>&apiKey=<鍵>`(鍵はサーバー側だけで使う。画面側は `jwtKey`)。メッセージは JSON(`messages` の配列を回す、という公式の例がある)
- 料金表: 無料の Community に WebSockets と「25 Cloud WebSockets」の記載がある。有料は Business(月額あり)。**今の鍵がどのプランかは、このリポジトリからは分からない**(鍵はサーバーの設定にあり、読んではいけない)
- 閉じるコード: 4404 = 配信中でない / 4429 = つなぎすぎ・早すぎ / 4555 = 1接続の寿命8時間 / 4005 = 配信終了 / 4401 = 鍵が違う / 4006 = メッセージが来ない
- 今の `tiktok-live-connector`(2.5.0)は、同じ会社の署名サービスを使って TikTok に直接つなぐ作り(署名だけ借りる)。公式 WebSocket は、会社のサーバーがイベントごと中継する別の道。connector の README も本番にはこちらを勧めている
- メッセージの中身(型の名前・項目名)は公式ページで確かめられなかった(`@eulerstream/euler-websocket-sdk` と `tiktok-live-proto` の型にある。新しいパッケージは入れない。`tiktok-live-proto` は node_modules に既にある)

## 完成の条件
- AC-1 確かめ: `ws`(既存)で `wss://ws.eulerstream.com` に今の鍵で1回だけつなぎ、配信中の相手でメッセージが届くか見る。鍵はサーバーの環境変数から読み、画面・ログ・コミット・報告に出さない。**本番の鍵を持つサーバーでは試さない。** めにくんが試す用の鍵と配信者を用意しなければ、ここで止めて報告する
- AC-2 使える(メッセージが届いた)と確かめられたら `src/euler-ws.js` に3つ目の道を作る。`tiktok-live-proto` の型で読み、`normalize.js` の形に直し、`ingest.md` の二重対策に乗せる(`source: 'euler-ws'`)。状態に出す。4401・4429 などで使えないと分かったら、実装せず、分かったことを報告して終える
- AC-3 接続は配信者1人につき1本。8時間(4555)で切れたら自動でつなぎ直す。4429 は待ちを倍にして再試行する。プランの上限(接続数)を超えそうなときは報告に書く

## 証拠
- 調査の結果を `docs/knowledge/decisions.md` に1行足す(個人名・金額・鍵の値は書かない)。実装したときは `test/euler-ws.test.js`(`ws` の偽サーバーで、メッセージ変換・4404/4429/4555 の再接続の待ち方を確かめる)
