# puchun-gift: パチンコ演出(4本)をギフトで流し、字と比率をダッシュボードで変えられるようにする

for: raikone-users
目的: 配信者は「ギフトが来たら派手に返す」を自分の言葉でやりたい。今の4本(chance・cutin・jackpot・puchun)は見本ページ(dev の try.html)でしか動かず、配信には使えない。ギフトで流れて、字を配信者が自分で書けると、ライコネを使う理由が1つ増える(数字は raikone-users)。

今ある物:
- 演出の本体: ブランチ `dev/puchun` のコミット 0dca6f1 と c04054a の `public/widgets/puchun/`(puchun.html・parts.js・fx.js・presets.js・try.html・README.md)。`?preset=`・`?ratio=`・字は `?キー=` で変えられる。まずこの2つを cherry-pick する
- ギフトで演出を流す前からの形: カットイン `cutin`(`public/widgets/lib/cutin.js`、`src/cutin-draw.js`)と、ギフトごとのルーレット(`roulettes`)。設定の持ち方・ダッシュボードの項目・ギフト名とコイン数の条件は、これと同じ形に合わせる(新しい形を作らない)
- 言葉はライコネの辞書 `docs/words.md`。画面の決まりは `~/ruu-work/skills/skills/kind-ui/SKILL.md`

完成の条件:
- AC-1 配信ソフトに入れる URL を1つ(`/widgets/puchun/puchun.html` に設定 id を付ける形など、今の widget と同じやり方)。ギフトが来ると、設定に合う演出が流れる。条件はギフト名かコイン数(ルーレットと同じ優先: ギフト名が先)
- AC-2 ダッシュボードで、条件ごとに「演出(4本から)」「字(その演出のキー全部)」「画面の比率(全画面・1:1・4:3・16:9)」を選べ、保存できる。保存した字がそのまま流れる。見本ボタンで、その場で1回流せる
- AC-3 連打(×5 など)は個数分すべて順に流す。上限や飛ばしは作らない(隠れた上限は禁止)。順に流すことは README とダッシュボードに書く
- AC-4 初めの状態は「使わない」。設定が無い配信者の画面は今と変わらない
- AC-5 テスト: 設定の保存と読み込み、ギフト名・コイン数での選び方、連打の数だけ流れること。既存の `npm test` も通る
- AC-6 一番上の README の機能の一覧に1行、`public/widgets/puchun/README.md` に設定の説明を足す
作らないもの: 新しい演出、立ち絵の差し替え(今は仮の影のまま)、本番の設定の書き換え
証拠: `npm test` の結果と、dev(3940)で「ダッシュボードで字を変えて保存 → 見本ボタン → 配信者が開く URL で流れた画面」をスマホ幅とパソコン幅で撮ったもの(確かめる人は作った人と別)

## 2巡目(レビューで見つかったもの)
- AC-7 ×200 のギフトが来ても、`puchun.html` が同時に持つ演出の iframe は常に1個以下で、前の演出が終わってから次が始まり、200本すべてが流れ終わる。
- AC-8 管理者が `puchuns` を使えない設定にした配信者では、設定に合うギフトが来ても演出が1本も流れない(他の機能と同じく `entitled('puchuns')` で止まる)。
- AC-9 `texts` に、選んだ演出の `fields` に無いキー(`play`・`ratio`・`preset`・`t`・`hold` など)や文字列でない値を入れて保存すると、保存が断られ、`puchun.html` の `query` に渡ることはない。
- AC-10 `texts` の1つの字が20字を超えると、保存が断られる(描画側の切り詰めと同じ長さ)。

## 完成条件を見直す
- 続いた指摘: 見本ボタンが無い(1巡目【直す】1つ目・2巡目 1)。あいまいな所: AC-2「見本ボタンで、その場で1回流せる」が、ボタンを置く画面・押したときに流れる先(ダッシュボードの中か、配信者が開く URL か)・サーバーの入口を決めていない。
- 続いた指摘: 字の入力が JSON の手書きで、演出ごとのキーの入力欄が出ない(1巡目【直す】5つ目・2巡目 2)。あいまいな所: AC-2「字(その演出のキー全部)を選べ」が、選んだ演出に合わせてキーごとの入力欄を出すことを書いておらず、JSON の入力欄でも満たせるように読める。
- 続いた指摘: 証拠の画面(`artifacts/shots/`)が無い(1巡目【直す】3つ目・2巡目 4)。あいまいな所: 「証拠」が誰が撮るか(作った人か、別の確かめる人か)・どこに置くか・撮るまで完成と言えないのかを決めていない。
