# ingest-status: つながり具合の表示と、外部ツールの設定の説明

仕事の種類: 配線 + 文章(ダッシュボードと使い方の画面)。前提: `ingest.md`(受け口の API)ができていること
見た目が変わるか: はい(ダッシュボードに1枚、使い方に1節。撮影が要る。本番に出す前にめにくんが見る)

目的: 配信者が「どの道が生きているか」「最後にいつ届いたか」を見られるようにし、TikFinity と Streamer.bot の設定をそのまま貼れる形で日本語で説明する。

作るもの(新しいファイル): `public/dashboard/ingest.js`(ES モジュール。CDN なし)
足すもの(共有ファイル。足すだけ): `public/dashboard/index.html`(接続の下に `<section id="ingestSection">` を1つ)、`public/dashboard/app.js`(`ingest.js` を読み込むだけ)、`public/dashboard/style.css`(必要な最小限)、`public/help/index.html`(節を1つ)
触らない: `src/` 全部(状態は `ingest.md` の `GET /api/ingest` を使う。足りないものがあれば、このカードで足さずに報告する)、`editor.js`、`simple.js`、ウィジェット
作らないもの: 新しいウィジェット、スキーマの項目、鍵の全文の保存(画面に出すのは作成の応答の1回だけ。再読み込みで消える)

## 画面
- 「接続の状態」: 行は2つ。①TikTok(直接)= `status.mode` を使う(つながっている / つなぎ中 / 未接続 / エラー)と最後にイベントが届いた時刻 ②外部ツール(受け口)= 鍵なし / 待機中 / 受信中と、最後に届いた時刻、受けた数・重複で捨てた数・多すぎて断った数。時刻は「3分前」の形。10秒ごとに `GET /api/ingest` を見直す(画面が隠れているときは止める)
- 色だけで状態を伝えない(言葉も出す)。1280幅・390幅 × 明・暗で崩れない
- 「受け口の鍵を作る」ボタン: 押すと鍵と、貼れる URL(`https://<このサーバー>/in/<鍵>`)を1回だけ出し、コピーのボタンと「この画面を閉じると二度と見られません」を添える。作り直しは確認を挟む(前の鍵が止まるため)。削除も確認
- 鍵がないときは、受け口を説明する1行と作るボタンだけ

## 使い方の節(`public/help/index.html` の `id="ingest"`)
書いてよいのは**公式の説明書で確かめた範囲だけ**。2026-10-18 時点で確かめたこと:
- TikFinity: 公式の Streamer.bot 連携ページ(https://tikfinity.zerody.one/streamerbot-integration)に、イベントに応じて使える差し込みがある: `%userId%` `%username%` `%nickname%` `%giftId%` `%giftName%` `%coins%` `%repeatCount%` `%likeCount%` `%totalLikeCount%` `%commandParams%`。フォローとシェアの差し込みは書かれていない(ユーザーの差し込みだけで足りる)
- TikFinity の Webhook の送り方(POST か GET か、JSON のキー名、URL に付けられる差し込み)は、公式の説明書では確かめられなかった(Webhook の項目に URL を貼る、までは第三者の資料に複数ある)。**確かめられていない部分は断定せず、「アプリの編集画面に出る項目名で合わせてください」と書く。** 例は「GET でクエリに項目を付ける形」にして、差し込みは上の公式の名前を使う
- Streamer.bot: 公式の説明書(https://docs.streamer.bot の Fetch URL)はこのセッションでは確かめられなかった。担当は説明書を開いて確かめ、確かめられたら書く。確かめられなければ節に「準備中」と書き、手順は書かない
各ツールの例は「ギフト」「いいね」「フォロー」「コメント」「シェア」を1つずつ、そのまま貼れる形で。鍵の場所には `<ここに鍵>` と書き、本物の鍵は書かない。二重に数えない仕組みと、送りすぎの上限(1秒20回)も1〜2行で書く。「困ったとき」の節に、受け口が 404(鍵違い)・429(送りすぎ)のときの見方を足す
