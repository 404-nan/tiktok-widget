# effect-log: ギフト1つずつと演出1つずつを記録し、「演出のあとギフトがどう変わったか」を配信のあとに出す

目的: ライコネが配信者のギフトを本当に増やしているかを、数字で言えるようにする(値段を決める・配信者に効果を見せる・演出を良くする元)。今の記録(src/history.js の data/sessions/)は1分ごとの合計で、「何のあとにギフトが来たか」が分からない。見た目(配信画面に出るもの)は一切変えない。

作るもの: src/effect-log.js(新)、src/history.js・src/hub.js(か、演出を配っているところ)・public/history/ の変更

完成の条件:
- AC-1 ギフト1つずつを、配信ごとの1行1つの JSON(data/sessions/<配信の id>.events.jsonl)に残す: 時刻(ミリ秒)、ギフトの id と名前、コイン、送った人の番号、その人のこの配信での何回目か。送った人の番号は、配信者(テナント)ごとの秘密の値で HMAC-SHA256 した値の頭 12 文字(名前やユーザー ID そのものは書かない)
- AC-2 演出1つずつを、同じファイルに残す: 時刻、種類(カットインの段階、ルーレットの結果、スロット、ガチャ、RUSH の始まりと終わり、ボスの命中・討伐、目標の達成、延長タイマーの延長)、主な値(段階、結果の名前、ダメージなど)。演出を決めているサーバー側の部品(roulette.js・rush.js・boss.js・slot.js・gacha.js など)が配るときに記録する。ウィジェットの見た目のコードは変えない
- AC-3 書き込みは、まとめて 1 秒ごとに追記する(1つずつ同期で書かない。配信を重くしない)。書けないときは log に1行出し、配信は止めない
- AC-4 配信のあと(切断か、demo の終わり)に、同じ配信の記録から「報告」を作り、data/sessions/<配信の id>.report.json に残す: 演出の種類ごとに、出た回数、出た前の 2 分と後の 30 秒・2 分の1分あたりのコイン(前と比べた倍率)、山(1分あたりのコインが、その配信の中央値の3倍を超えた分)の時刻と、その前 2 分に出た演出
- AC-5 管理の画面の「記録」(public/history/)に、配信ごとの報告を表で出す(文字と数字だけ。グラフは次)。これは配信画面ではなく、配信者が見る管理の画面
- AC-6 記録は 90 日で消す(設定で変えられる)。消すのは1日1回
- AC-7 テストのギフト(テスト送信・デモ)は、記録に「テスト」の印を付け、報告の数字には入れない(今の「テスト送信は本番の数を汚さない」と同じ)
- AC-8 送った人の名前・ユーザー ID・アイコンの URL が、events.jsonl と report.json のどこにも無いことをテストで確かめる
- AC-9 今あるテストは全部そのまま通る。配信画面のウィジェット(public/widgets/)の見た目は変えない
作らないもの: 山の画面の写し(次)、グラフ、配信者をまたいだ集計
