# ai-screenshot: テスト送信後のウィジェットを開発環境で撮る
仕事の種類: 配線
見た目が変わるか: 変わらない。開発用 MCP の返却に画像を加えるだけ。

目的: AI が対象ウィジェット、テスト送信、待ち時間を1回の依頼で指定し、開発サーバー上の表示を画像で確認できるようにする。
テスト送信を先に行い、指定したミリ秒だけ待ってから、既存のウィジェット URL を開発環境で撮影する。
撮影は見た目の確認用であり、配信・本番・永続記録の操作ではない。

触ってよいファイル:
- `src/ai-screenshot.js`: 対象 URL の検証、テスト送信、待機、撮影、画像返却を分ける。
- `src/ai-mcp.js`: `take_widget_screenshot` の入力説明と画像コンテンツの返却を追加する。
- `mcp/server.js`: 開発サーバーを向く MCP から道具を呼べるようにする。
- `server.js` または開発用の MCP 接続部: `/ai/mcp` から使う場合の開発環境判定を渡す。
- `test/ai-screenshot.test.js`、必要なら撮影処理のテスト用 fixture。

触らないファイル:
- 本番ポート・本番ホスト、`config.yaml`、`data/`、本番テナントの記録。
- `public/widgets/` の表示コード、外部 CDN、ウィジェットの設定、TikTok への実イベント送信。
- 任意の外部 URL、ローカルファイル、管理画面、OBS の画面を撮る仕組み。
- 新しい撮影ライブラリの導入。既存の開発環境で使える撮影手段で足りない場合は別途確認する。

依頼から返却まで:
- AI の入力はウィジェットの識別子、`test_event` と同じイベントの値、待機ミリ秒、必要なら画面サイズとする。
- まずテナント範囲と開発環境を確認し、次にテスト送信、表示の安定待ち、撮影の順で実行する。
- 待機中にページを再読み込みしてテスト状態を消したり、別ウィジェットへ移動したりしない。
- 返却は MCP の画像ブロックと短い日本語の撮影結果。巨大な base64 をログや監査に書かない。
- 撮影の一時ファイルが必要なら処理終了時に削除し、同じファイル名を使い回さない。
- 画像の縦横比やサイズは、対象ウィジェットの既存の推奨サイズを初期値にする。

失敗時の約束:
- テスト送信が拒否・失敗したら撮影を始めず、失敗理由と実行段階だけを返す。
- ページの読み込み、WebSocket 接続、指定待機時間のいずれかが失敗したら成功画像を返さない。
- スクリーンショット機能が未導入の環境では、依存を勝手に追加せず、必要な準備を日本語で返す。
- 開発サーバーが停止している場合は再起動せず、接続できない理由で終える。

見た目の確認範囲:
- テスト送信で出る演出、表示の消え方、文字の欠け、画像の読み込みを確認できる。
- 分析用の集計や effect-log の report はこの道具の成功・失敗に影響させない。

完成の条件:
- AC-1 MCP に `take_widget_screenshot` を追加し、対象ウィジェット、テスト送信の種類と値、待ち時間ミリ秒を名前で指定できる。
- AC-2 対象 URL は開発サーバーが返す自分のテナントのウィジェット一覧からだけ選び、入力で任意 URL を渡せない。
- AC-3 テスト送信は既存の `test_event` と同じ開発環境限定の処理を使い、配信中の実イベントを作らない。
- AC-4 テスト送信の完了を確認してから待機を始め、待機時間は 0 以上の整数で上限を設ける。範囲外は撮影せず日本語で理由を返す。
- AC-5 待機後に対象ページを撮影し、MCP の `image` コンテンツとして PNG または既存の撮影手段が返す画像を返す。
- AC-6 画像と一緒に対象ウィジェット、テスト送信の種類、待ち時間、撮影時刻を返す。送信者情報やトークンは返さない。
- AC-7 開発環境以外の `/ai/mcp` は 404 または拒否を返し、ブラウザ起動・テスト送信・撮影を一切行わない。
- AC-8 `TW_SERVER` が開発サーバーでない、テナントが許可されていない、またはウィジェットが見つからない場合は撮影しない。
- AC-9 失敗時は一時画像や一時ページを残さず、日本語の理由を返す。開発サーバーや本番サービスを再起動しない。
- AC-10 既存の `read`・`test`・テナント範囲の確認を通し、`*` のトークンでも対象テナントを省略した全件撮影を許さない。
- AC-11 テスト送信の結果が画面に反映される前に撮影しない。反映不能・タイムアウト時は画像を成功扱いで返さない。
- AC-12 同じテスト入力と待ち時間で、指定したウィジェットだけが撮影対象になり、別の画面や管理画面が写らない。
- AC-13 `test/ai-screenshot.test.js` で本番拒否、任意 URL 拒否、待ち時間の上限、対象テナント境界、画像返却を確認する。
- AC-14 実ブラウザを使う確認は開発サーバー 3940 または専用の一時サーバーに向け、本番 3939 と本番ホストには触れない。
- AC-15 `npm test` が緑で、既存の MCP・テスト送信・ウィジェットのテストを壊さない。

作らないもの: 本番撮影、配信中の撮影、任意サイトのブラウザ、撮影画像の永続保存、画像編集、スクリーンショットを返す管理画面。

証拠: `test/ai-screenshot.test.js`、開発サーバーでの MCP 受け入れ確認、必要なら一時画像の後始末確認、`npm test`。

めにくんに決めてほしいこと: 返す画像の標準サイズと、撮影手段が使えない環境で新しい依存を追加せずに止めるか。
