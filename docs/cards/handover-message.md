なぜ要るか(配信者): 新しい配信者の入口は、管理画面が出す短い URL `/d/<短いID>` と4桁の数字。管理画面は URL の欄と数字の欄を別々に出すだけで、送る文は毎回手で書く。最初に届く文に、開き方と、開いたあと何をするかが無いと、受け取った人はそこで止まる。first-run-walk は空のデータの画面から歩いたので、ここは見ていない。新しく使い始めた人は 10/19〜11/1 で0人。これが増えない原因とは断定しない。
前提(確かめた): 配信者の行の描画は public/admin/admin.js。URL の欄は同じファイルの `copyField`、数字は382行あたりの `.pin-value`、数字の作り直しは `/tenants/:id/repin`。server.js の `tenantView` が pin と URL を返す。kind-ui を読む。言葉は docs/words.md に合わせる。開発 3940 と本番 3939 は触らない。テストは url-first-choice.test.js と同じく、空いた番号と一時のデータで起動する。

## 完成の条件
テストは本物のサーバーと本物のブラウザで確かめる。
- AC-1 管理画面の配信者の行に「案内文をコピー」のボタンが1つある。押すとコピーされ、コピーしたと画面に出る。
- AC-2 コピーした文には、その配信者の短い URL(`/d/<短いID>`)と4桁の数字がそのまま入る。`/t/<鍵>/` の URL は入らない。
- AC-3 コピーした文は8行以内で、順に ①URL を開いて数字を入れる ②出すものを選ぶ ③配信ソフトに URL を入れる ④ためす が分かる。「テナント」「ウィジェット」「トークン」の語を使わない。説明なしで高校生が読める文にする。
- AC-4 数字を作り直したあとにコピーすると、新しい数字が入る。
- AC-5 文の中の URL を開いて文の中の数字を入れると、その配信者のダッシュボードが開く。
- AC-6 既存のテストが全部通る。

## 作らないもの
配信者への自動送信、メール・Discord への送信、サインアップの画面、文を編集する欄、数字や URL の仕組みの変更。

## 証拠
受け入れテストと、ボタンの写真を artifacts/shots/ に置く。レビュー役はコピーされた文の全文を読み、初めての人が次に何をするか分かるかを確かめる。文に実在の配信者の名前と数字を載せない(テストの一時データだけ)。LIVE Studio には関係しない。
