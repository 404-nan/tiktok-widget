# ootori: 最後の一投とエンドロール
仕事の種類: 作り込み
見た目が変わるか: 変わる

目的: 配信者がラスト10分を始め、最後に受けたギフトの送信者を大トリにする。終了時は参加者を日本語のエンドロールで残す。

## 作るもの(触ってよいファイル)
- 新規: `src/ootori.js`、`public/widgets/ootori.html`
- 足す: `src/schema.js`、`src/runtime.js`、`src/admin.js`、`mcp/server.js`、`bin/tw.js`、`public/dashboard/simple.js`
- 新規テスト: `test/acceptance/ootori.test.js`、`test/ootori-wiring.test.js`

## 触らないファイル
- `config.yaml`、`data/`、既存のランキング・履歴の集計、ギフト名の対応表、既存テストの書き換え。
- TikTokから配信終了を推測する処理、外部素材、外部CDNは作らない。

## 完成の条件
- AC-1 `start` 操作でラスト10分状態を開始し、開始前のギフトは大トリ候補にしない。開始後の有効なギフトを受けるたび、席の名前・時刻・送信者をサーバーで置き換える。
- AC-2 初期方式は「誰でも式」とし、ラスト10分中のどの有効なギフトでも席を取れる。`raise` 方式を選んだ場合だけ、現在の席を上回る条件を満たすギフトに限定する。境界値と比較方法を設定に書く。
- AC-3 席の差し替えは0〜700msで完了し、0.2〜0.4秒以内に新しい送信者の名前とアイコンを表示する。席が変わるたび、WebAudioの乾いた音を1回だけ鳴らす。
- AC-4 `finish` 操作で席を閉じ、最後の送信者を大トリとして固定する。二重押しは同じ結果を返し、追加のエンドロールを起こさない。
- AC-5 終了の入りは600msの無音と暗転、続く2500ms以内に「本日の大トリ」と名前を出す。ここまでの主演出は3秒以内に収める。
- AC-6 エンドロールは参加者を重複なく最大20組ずつ上へ流し、20組を超えた分は最後に「ほか○人」とまとめる。最初の送信者を先頭、大トリを最後に置く。
- AC-7 表示名は既存のNG判定と表示用の安全化を通し、未表示の名前をログへ残さない。名前を画面へ出すときは文字列として扱い、HTMLを実行しない。
- AC-8 エンドロール全体は締めの特別枠として最大9000ms。3秒の例外を認めない場合は、AC-6の一覧を3秒以内に静止表示へ切り替えられる設定を用意する。
- AC-9 `event` と `testEvent` を分離し、テスト送信は大トリ・参加者・履歴を汚さない。再接続時は席、残り時間、終了済み状態をサーバーから復元する。
- AC-10 画面はES5、外部素材・CDNなし。色は席を金、締めを虹にし、点滅は1秒3回以下、効果音はWebAudioだけにする。

## 状態と失敗時
- `start` 前は `idle`、ラスト10分中は `open`、席を閉じた後は `closed`、エンドロール中は `rolling` とする。
- `start` の二重押しは残り時間を延ばさず、現在の席と終了予定時刻を返す。
- `finish` 前に接続が切れても、最後に確定した席と参加者をサーバー状態から復元する。
- `finish` 後のギフトは大トリを変更せず、通常の他の演出へだけ渡す。
- 参加者の名前がNG判定で除外された場合は人数だけを残し、空の札を作らない。
- 参加者が0人ならエンドロールを出さず、「参加者なし」の日本語の状態だけを返す。

## 演出の境目
- 席の札は画面上部に置き、右列とコメント欄を覆わない。
- 席が替わる音は一段ずつ変えるが、音量を上げ続けずWebAudioの音域内に収める。
- 終了時は0.6秒の無音後に拍子木を1回だけ鳴らし、大トリを金で中央に出す。
- エンドロールの名前は1画面に最大20組、読める速度で流し、最後の札だけを大きくする。
- 明るいテーマでも金文字と白文字のコントラストを保ち、半透明の薄い文字を使わない。

## 作らないもの
