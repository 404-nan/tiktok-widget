# ai-analysis: 配信と演出の効き目を集計で読む
仕事の種類: 配線
見た目が変わるか: 変わらない。MCP と `/ai/v1` の返り値だけを増やす。

目的: effect-log が残す1配信分の `events.jsonl` と `report.json` から、AI が集計済みの振り返りを受け取れるようにする。
送信者の名前・ユーザー ID・アイコン URL・送信者を特定できる値は返さない。
既存の記録を読み取り、元ファイルを書き換えずに結果を返す。

触ってよいファイル:
- `src/ai-api.js`: 読み取り用の道具と `/ai/v1` の経路、権限・テナント確認を追加する。
- `src/ai-mcp.js`: MCP の道具名、入力説明、日本語のエラーを追加する。
- `mcp/server.js`: リモート MCP から同じ道具を呼べるようにする。
- `src/effect-analysis.js`: `events.jsonl` と `report.json` を読む集計処理を分離して置く。
- `test/ai-analysis.test.js`: 一時ディレクトリの記録を使う受け入れテストを追加する。

触らないファイル:
- `data/`、`config.yaml`、本番のテナント記録、既存の `events.jsonl` と `report.json`。
- `src/effect-log.js` と演出を配る部品。記録形式は effect-log カードを正とする。
- `public/widgets/` と配信画面。新しい集計を画面には出さない。
- 送信者の名前・IDを返す既存の履歴表示や、課金・接続設定の仕組み。

入力と返り値の約束:
- 対象は1配信または指定期間の集計。期間の端はミリ秒の時刻で受け、対象外の記録を混ぜない。
- 配信が指定されない場合は、現在の `get_history` と同じく、許可されたテナント内の一覧だけを候補にする。
- 返り値は `summary`、`peaks`、`effects`、`frequentEffects`、`insufficientEffects` のような集計単位にする。
- 件数が0のときも空配列と「記録がない」理由を返し、例外や空の成功を返さない。
- 倍率は分母が0または比較不能なら数値を作らず、`null` と理由を返す。
- 演出やギフトの表示名は既存記録の値を使い、自分で翻訳したギフト名を作らない。

安全境界:
- `read` は記録を読む権限であり、`write`、`operate`、`test`、`admin` を暗黙に付けない。
- `tenant` は認証済みトークンの範囲で照合し、HTTP の query/body とファイルパスを混同しない。
- AI の要求文に別テナントの id や送信者の検索条件があっても、許可された集計以外は拒否する。

実装時の確認:
- report の前後1分・2分の定義が effect-log と一致し、境界時刻をテストで固定する。
- events の読み取り順が崩れていても、時刻順に並べ直すか不完全として明示する。
- 大きな配信記録を一度に返しすぎず、集計後の結果だけを返す。

完成の条件:
- AC-1 `analyze_effects` など、名前だけで仕事が分かる読み取り道具を MCP と `/ai/v1` の両方から使える。
- AC-2 入力は対象テナントと配信の id、必要なら対象期間に限定し、対象を省けるのは現在のトークンが1テナントだけを持つ場合に限る。
- AC-3 `/ai/v1` と MCP は Bearer トークンを必須にし、現在の `read` scope が無いトークンを拒否する。
- AC-4 トークンのテナント一覧に無いテナントは拒否し、`*` のトークンでも対象テナントを明示しない全件取得は許さない。
- AC-5 読む場所は対象テナント配下の配信記録だけ。別テナントのファイルを推測したパスや任意パスは受け付けない。
- AC-6 `report.json` の集計を使い、`events.jsonl` で演出と前後のギフトの時系列を確認して結果を作る。片方が無いときは推測せず、日本語の不足理由を返す。
- AC-7 「山」は1分あたりコインの増加と時刻、山の前に出た演出の種類を、送信者情報なしで返す。
- AC-8 演出の種類ごとに、出た回数、出る前後の1分あたりコイン、比較倍率または比較不能の理由を返す。
- AC-9 よく出る演出と、比較対象が足りず「効き目を判定できない」演出を分けて返す。効かないと断定しない。
- AC-10 返却 JSON に送信者の名前、TikTok ユーザー ID、アイコン URL、HMAC 値、元イベント行、ユーザー単位の順位を含めない。
- AC-11 配信 id、演出名、ギフト名など集計に必要な非個人情報だけを返し、秘密の設定・Bearer 値・監査の生データを返さない。
- AC-12 読み取りなので `TW_AI_WRITE` の有無に関係なく使えるが、設定変更・操作・テスト送信を副作用として行わない。
- AC-13 既存の `/ai/v1` の 401・403・404 とテナント境界を壊さず、監査には道具名と対象テナントだけを残す。
- AC-14 記録が壊れている行を理由なく捨てて数字を確定せず、読み取れた範囲と不完全であることを日本語で返す。
- AC-15 `test/ai-analysis.test.js` で別テナント拒否、read scope、送信者情報の不在、山・前後1分・頻出集計を確認する。
- AC-16 `npm test` が緑で、既存の effect-log テストを変更せず通る。

作らないもの: 分析結果の画面、グラフ、配信者をまたいだ比較、送信者ランキング、個人別の効果判定、値段や契約に関する提案。

証拠: `test/ai-analysis.test.js`、既存の `test/effect-log.test.js`、`npm test`。

めにくんに決めてほしいこと: 道具名を `analyze_effects` に固定するか、山・演出効果・頻出演出を別の読み取り道具に分けるか。
