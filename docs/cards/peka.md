# peka: 遅れて光る告知ランプ
仕事の種類: 作り込み
見た目が変わるか: 変わる

目的: ギフトの直後に派手な画面を出さず、サーバーが決めた時刻に隅のランプだけを光らせる。光った人が主役になり、待つ時間も演出にする。

## 作るもの(触ってよいファイル)
- 新規: `src/peka.js`、`public/widgets/peka.html`
- 足す: `src/schema.js`、`src/runtime.js`、`src/admin.js`、`mcp/server.js`、`bin/tw.js`、`public/dashboard/simple.js`
- 新規テスト: `test/acceptance/peka.test.js`、`test/peka-wiring.test.js`
- 既存の `src/hub.js` の `event`・`testEvent`・`reset` を購読する。ハブ本体は変えない。

## 触らないファイル
- `config.yaml`、`data/`、`src/gift-names-ja.json`、既存のカットイン画面とそのテスト。
- ギフト名は GiftID から対応表を引き、未登録は受信した名前を使う。翻訳は足さない。

## 完成の条件
- AC-1 設定は `enabled`、`minCoins`、`chance`、`bonusSeconds`、`sound`、`volume` を持ち、値の範囲と説明は日本語で `src/schema.js` に定義する。`chance` は0〜1、`volume` は0〜1。
- AC-2 条件を満たす1件のギフトにつき抽選は1回だけ行う。`gift.count` が複数でも抽選を増やさない。結果と光る時刻はサーバー状態に保存する。
- AC-3 当たりの遅延は、先ペカ20%(0ms)、後ペカ70%(1500〜6000ms)、遅ペカ10%(9000〜11000ms)の3種類からサーバーが決める。乱数の結果を画面側で決めない。
- AC-4 光る瞬間は120ms以内にランプを消灯から点灯へ切り替え、点滅させない。点灯から300ms以内に送った人のアイコンと名前を見せる。
- AC-5 光る演出は光る時刻から1400ms以内に収まり、ランプは `bonusResolved` を受けるまで点灯を続ける。解決前の別の当たりは上限なく全部順番待ちにする（投げた分を捨てない）。
- AC-6 画面を読み込み直しても `GET /api/peka` と WebSocket の状態から点灯・待ち・送った人を復元できる。状態はクライアントだけに持たせない。
- AC-7 配信中の `testEvent` は本番抽選・履歴・集計に入れず、開発環境だけで画面確認用のテスト状態を配る。`event` のテストは接続開始時のリセットで消す。
- AC-8 ランプの色は青<緑<赤<金<虹の順で、光る瞬間の点滅は0回、効果音は WebAudio 合成の「カコッ」1音以下にする。派手な音はボーナス開始側に任せる。
- AC-9 公開画面はES5、外部CDN・外部素材なし。開始から3秒以内、送った人の表示を最初の0.2〜0.4秒に置き、右列と下を隠さない。

## 状態と失敗時
- 抽選前は `idle`、当たりを待つ間は `pending`、点灯中は `lit` とし、状態名は画面へ出さない。
- サーバー時計が戻った場合は、予定時刻を現在時刻より前へ戻さず、ただちに点灯へ進める。
- WebSocketが切れている間に予定時刻を過ぎても、再接続時の状態を正として1回だけ点灯する。
- 設定が壊れている、または `enabled: false` のときは抽選せず、既存の画面や集計へ影響を出さない。
- ボーナス解決の通信が失敗してもランプは消さず、管理者が再試行できる状態を返す。
- 待ち行列を超えた当たりは捨てず、サーバーの上限と受け付け時刻をテストで確認できるようにする。

## 演出の境目
- 送信者の名前はランプの横に置き、12文字を超える表示は末尾を省略する。
- アイコンが読めないときは壊れた画像を出さず、名前だけを同じ位置に残す。
- ランプの点灯は一度だけで、明滅・虹色の高速変化・画面全体の覆いを使わない。
- テスト画面では「テスト」を小さく付けるが、本番のランプと同じ抽選結果にはしない。
- スマホ幅で名前とランプが重ならず、明るい背景でも墨の面と白文字のコントラストを保つ。

## 作らないもの
