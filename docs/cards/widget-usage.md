# widget-usage: どの配信でウィジェットを使ったかを、配信の記録に残して見せる
仕事の種類: 配線
見た目が変わるか: 少し変わる(統計の画面に1列・1行足すだけ。配信画面は変えない)

目的: 今は配信者ごとに、つながる配信を全部記録している。そのうち「OBS(や LIVE Studio)にライコネのウィジェットを入れて配信した」配信を見分ける。請求と効果の分析の元にする。配信者は何もしなくてよい。

考え方: OBS 用の鍵(役目 `obs`)でつながっている WebSocket が1つ以上ある時間を「ウィジェットを使っていた時間」とする。ダッシュボード(役目 `owner`)は数えない。`src/hub.js` の `hasClient('obs')` と `'client'` イベント、`ws.on('close')` がもうある。

## 触ってよいファイル
- `src/history.js`(配信1回分の記録に足す)、`src/runtime.js`(hub と記録をつなぐ)、`src/hub.js`(必要なら、obs の接続が0→1・1→0 になったことを知らせるイベントを足すだけ)
- `public/history/history.js`・`history.css`(統計の画面)
- 新規テスト `test/widget-usage.test.js`、`test/README.md`、`src/README.md`、`public/history/README.md`(あれば)、一番上の `README.md` の機能の一覧

## 触らないファイル
- `config.yaml`、`data/`、公開ウィジェット(`public/widgets/`)、課金の処理(`src/billing.js`)

## 完成の条件
- AC-1 配信1回分の記録(`toJSON` などで保存される形)に `widgetMs`(その配信のあいだ、obs の接続が1つ以上あった合計ミリ秒)と `widgetUsed`(真偽)を足す。`widgetUsed` は `widgetMs` が配信の長さ(durationMs)の半分以上なら真
- AC-2 配信の途中で obs の接続が増えたり減ったりしても、重ならないように合計する(2つ同時につながっていても2倍にしない)。配信の始まる前からつながっていた分は、配信の開始時刻から数える
- AC-3 ダッシュボード(owner)やモニターの接続は数えない。テスト送信・デモの配信は今の記録と同じ扱い(数えない形が今あるなら合わせる)
- AC-4 統計の画面(`/history/`)の配信の一覧に「ウィジェット」の列を足し、「使った 2時間13分」か「使っていない」を出す。1回分の詳しい画面にも同じ1行を出す。文字は日本語
- AC-5 古い記録(`widgetMs` が無い)は「記録なし」と出し、落ちない
- AC-6 1人用(local、`id === 'local'`)では、OBS の画面も役目 `owner` でつながるので、`widgetMs` は記録しない(`null`)。画面は「記録なし」
- AC-7 テストを足す: 接続の増減の合計、半分の基準、owner を数えない、古い記録の表示。`npm test` を全部通す
- AC-8 README を同じ変更で直す(`src/README.md` の該当行、`test/README.md` にテストを1行、一番上の README の機能の一覧に1行)

## 状態と失敗時
- 時刻は `Date.now()` を使い、テストでは差し替えられる形にする(今の history.js の流儀に合わせる)
- 数え間違いより「少なめに数える」ほうを選ぶ(請求の元になるため)
