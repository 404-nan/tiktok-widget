# puchun-e2e: パチンコ演出を、本物のサーバーと本物のブラウザで「ギフト → 画面に出る」まで確かめる

for: 北極星
仕事の種類: 確かめる(テストを足す。直すのは、テストで壊れていると分かったときだけ)
見た目が変わるか: 変わらない

目的: パチンコ演出(v2026.10.30-2 で出した)は、選び方・連打・設定の保存を部品ごとに確かめただけで、「配信者がダッシュボードで設定 → ギフトが届く → 配信ソフトの URL に演出が出る」を通しで見たことがない。配信者が初めて使って何も出なければ、二度と使わない。

前提: 本番(3939)は使わない。テストは一時フォルダの設定でサーバーを別のポートで立てる(他の受け入れテストと同じやり方を repo から探して合わせる)。ギフトはダッシュボードの「テスト」と同じ道(サーバーの試しのイベント)で送る。

## 触ってよいファイル
- 新規 `test/acceptance/puchun-e2e.test.js`、`test/acceptance/README.md`
- テストで壊れていると分かったときだけ: `public/widgets/puchun/`、`src/puchun.js` と、その直しに要る最小の場所

## 触らないファイル
- `style.css`、ダッシュボードの見た目、他の演出

## 完成の条件
- AC-1 テストが一時の設定でサーバーを立て、`puchuns` に「バラで jackpot、字は『テスト当たり』」の1件を API で保存する
- AC-2 実ブラウザ(playwright)で配信ソフトの URL(`/widgets/puchun/puchun.html` に、ダッシュボードが出すのと同じ問い合わせ)を開き、試しのイベントでバラ×1 を送ると、10秒以内に画面に「テスト当たり」が見える
- AC-3 バラ×3 を送ると、演出が3回流れ終わる(数え方は画面の中の印か、流れた回数を見られる所。テストのためだけの本番コードは足さない)
- AC-4 合わないギフト(バラ以外)では何も出ない
- AC-5 playwright が無い環境では skip ではなく失敗にする。`npm test` が全部通る

作らないもの: 新しい演出、見た目の変更、テスト専用の口

## 証拠
- AC-2 の瞬間の画面 1280×720 を `artifacts/shots/puchun-e2e.png` に
- `npm test` の最後の数行

## 状態と失敗時
- 本番(3939)の再起動・書き込みはしない。壊れていたら、直した場所と原因を1行ずつカードの末尾に書く
