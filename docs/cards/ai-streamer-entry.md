# ai-streamer-entry: 配信者自身の AI を安全に接続する
仕事の種類: 配線
見た目が変わるか: 変わる。配信者用ダッシュボードに AI 接続の説明・発行・取り消し・コピーを足す。

目的: 配信者が自分の外部 AI から、自分のテナントだけを読んだり設定案を作ったりテスト送信したりできる入口を用意する。
トークンの発行と取り消しは配信者用ダッシュボードの所有者権限で行い、値は発行直後だけ表示する。
本番設定の反映は既存の承認・取り消しの流れを使い、配信中は設定変更をしない。

触ってよいファイル:
- `src/ai-tokens.js`: テナント限定と、読み取り・設定提案・テスト送信だけの権限を表す。
- `src/ai-api.js`: 入口から発行したトークンの境界、dry-run、承認、取り消しを接続する。
- `src/ai-mcp.js`、`mcp/server.js`: コピーした接続設定で MCP が同じ範囲を使えるようにする。
- `src/runtime.js`、`server.js`: 所有者のダッシュボードから自分のテナントだけを管理する API を追加する。
- `public/dashboard/index.html`、`public/dashboard/app.js`、必要な共通 CSS: 日本語の入口を追加する。
- `public/help/index.html` または `docs/guide/`、`test/ai-streamer-entry.test.js`。

触らないファイル:
- `config.yaml`、`data/`、本番のトークン・テナント記録、既存の個人情報。
- `public/widgets/` と配信画面。接続入口の追加でウィジェットの表示を変えない。
- 管理者だけの全テナント用トークン画面と、課金・接続・切断・再起動の API。
- トークンの平文をログ、監査、HTML、コミットに残す処理。

利用者の流れ:
- 配信者は自分のダッシュボードを開き、できること・できないことを読んでから発行する。
- 発行後は接続設定をコピーし、外部 AI 側に貼り付ける。トークンをチャット本文や URL に含めない。
- 最初の依頼は読み取り、次に設定案の dry-run、最後に開発環境のテスト送信とする。
- 提案の差分を配信者が確認し、本番反映が必要なら既存の承認画面で判断する。
- 使い終わったトークンは画面から取り消せる。期限も一覧で確認できる。

トークンの扱い:
- トークン一覧には名前、対象テナント、権限、期限、最終使用時刻だけを表示し、値は表示しない。
- 取り消しは対象テナントの所有者が自分の発行分だけに行える。別の発行元の値を推測できない。
- 接続設定を再表示するためにトークンを復号したり、ブラウザ保存領域へ自動保存したりしない。
- エラー画面は期限・権限・テナントのどれで拒否したかを日本語で示すが、秘密値は示さない。

本番境界:
- dry-run の結果には `live`、設定の版、差分、検証結果を含め、反映の可否を AI が誤認しないようにする。
- 既存の承認待ちは管理画面の監査と同じ id で追えるが、AI が承認 API を直接呼べないようにする。
- 配信中の設定提案はできても、保存・undo・操作は配信中の安全柵に従う。

完成の条件:
- AC-1 テナントのダッシュボードに「AI との接続」を日本語で表示し、何ができて何ができないかを先に説明する。
- AC-2 所有者の画面で発行するトークンは対象テナントを1つだけ持ち、全テナント指定、別テナント指定、管理者 scope を選べない。
- AC-3 権限は読み取り、設定の提案、開発環境のテスト送信だけ。実際の設定保存・操作・課金申請はこの入口のトークンから拒否する。
- AC-4 設定の提案は必ず dry-run の差分・検証結果・配信中かどうかを返し、保存ボタンや保存 API を直接実行しない。
- AC-5 本番設定を反映する必要がある場合は既存の承認待ち・人の承認・取り消しの記録へ渡し、配信中は反映しない。
- AC-6 テスト送信は既存の `test_event` と同じ開発環境限定の扱いにし、ランキング・履歴・集計・永続状態を変えない。
- AC-7 発行画面はトークンの値を発行直後の一度だけ表示し、「コピー」と再表示しない注意を出す。保存するのは照合用の要約だけにする。
- AC-8 取り消し後は同じ値の Bearer 認証を 401 にし、画面の一覧からも使用中として扱わない。
- AC-9 MCP の接続設定は `/ai/v1` または開発用 `/ai/mcp` の接続先、トークンの入れ場所、テナント指定方法をコピーできる。値そのものをURLやログに埋め込まない。
- AC-10 接続設定と説明は日本語で、Claude・ChatGPT など外部 AI に貼る場所、最初に読む道具、dry-run とテスト送信の順を案内する。
- AC-11 OBS 用の鍵やダッシュボード閲覧者の権限では発行・取り消しできず、テナント所有者の画面からだけ操作できる。
- AC-12 期限切れ、取り消し済み、別テナント、書き込み・操作 scope の要求は日本語の理由を返す。
- AC-13 既存の `/ai/v1` の Bearer・scope・テナント範囲・監査・undo と矛盾しない。トークンの値と個人情報を監査に書かない。
- AC-14 PC とスマホ幅で発行、コピー、取り消し、失敗表示が押しやすく、見た目の文字は日本語である。
- AC-15 `test/ai-streamer-entry.test.js` で自分のテナント限定、OBS 権限拒否、提案の未保存、テスト送信の非永続性、失効を確認する。
- AC-16 `public/help/index.html` または `docs/guide/` に、発行から AI 側の登録、dry-run、テスト、取り消しまでの日本語手順を書く。
- AC-17 `npm test` が緑で、既存のトークン・承認・ダッシュボードのテストを壊さない。

作らないもの: 自動で本番設定を保存するボタン、配信中の設定変更、接続・切断・再起動、課金の即時反映、全テナントを見られる配信者用トークン。

証拠: `test/ai-streamer-entry.test.js`、既存の AI API・トークン・承認テスト、必要なら開発サーバーの画面確認、`npm test`。

決めたこと: 設定の提案だけの scope を新しく足す(名前は `suggest`)。今の write scope に属性を足すより、範囲が名前で分かり、ほかの入口と混ざらない。
